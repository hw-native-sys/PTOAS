# 自动同步选项

## 作用

自动同步选项用于减少用户手工插入同步操作的负担。

它主要影响编译输出中同步相关行为的处理方式。

## 相关参数

`ptoas` 提供两个自动同步选项，**默认全部关闭**：

| 选项 | 默认值 | 作用 | 前置条件 |
|---|---|---:|---|
| `--enable-insert-sync` | 关闭 | 启用常规自动同步插入 | 无 |
| `--enable-inject-barrier-all-sync` | 关闭 | 在 memory-effecting 的 pipe 操作前插入 `pto.barrier PIPE_ALL`，以更保守的方式满足同步 | 无 |

### 两个选项互斥

两个选项**一次只能启用一个**。同时指定，`ptoas` 会在编译早期直接报错并终止，不会退化到其中某一种同步策略。

## 默认建议

两个选项全部关闭时，`ptoas` 不做任何自动同步插入，同步关系完全由程序显式表达。如果你希望先快速跑通常规场景，建议优先尝试：

```bash
--enable-insert-sync
```

## 什么时候调整

建议在以下场景调整自动同步选项：

- 不想一开始手工写同步
- 怀疑问题与同步不足有关
- 需要用更保守的方式做排障

## 可观察到的效果

切换同步模式后，用户通常会观察到：

- 同步相关错误表现不同
- 某些程序在一种模式下可通过、在另一种模式下行为不同
- 更保守的模式更适合确认问题是否与同步有关

启用常规自动同步后，对于非嵌套、无分支、常量边界且步长为 1 的多槽轮转循环，编译器会尝试消除已被其他同步路径完整覆盖的重复等待。覆盖判断同时区分物理槽位和循环轮次，保留加载就绪、计算完成、存储完成及槽位复用所需的顺序关系，并匹配首轮和退出时的槽位事件。

这可以减少同步事件占用，降低因事件资源不足而引入全流水等待的可能性。无法证明覆盖关系的情况会保留原有同步；该优化不保证所有循环都能消除全流水等待。无需额外启用选项。

## 常见用法

```bash
ptoas input.pto --enable-insert-sync -o output.cpp
```

```bash
ptoas input.pto --enable-inject-barrier-all-sync -o output.cpp
```

## 排查建议

如果怀疑问题与同步有关，建议：

1. 先尝试常规自动同步
2. 如果问题仍存在，再切换到更保守模式
3. 再回头检查程序中的 producer-consumer 关系是否表达清楚

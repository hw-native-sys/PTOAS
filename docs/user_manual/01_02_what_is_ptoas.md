# 1.2 什么是 PTOAS

## 1. 概述

`ptoas` 是 PTO 程序的主要编译入口。它负责把 `.pto` 文本检查为合法输入，并最终生成可调用的输出代码。

从用户角度看，`ptoas` 主要不是“一个库函数”，而是三类能力的组合：

- 命令行编译工具
- `PTO ISA` 的编译支持
- Python 绑定与脚本化构造入口

## 2. PTOAS 是什么

`ptoas` 可以理解为围绕 `PTO ISA` 组织的一套完整工具链，主要职责包括：

- 解析 `.pto`
- 验证 PTO ISA 的结构、类型和目标相关约束
- 按用户选择的选项处理布局、地址和同步等问题
- 输出后续可调用代码

它位于：

- 上游 PTO 程序构造层
- 下游目标相关代码生成层

之间，是 PTO 程序的主要结构化编译入口。

## 3. 用户最常接触的输入与输出

### 3.1 输入

- `.pto`：PTO 文本

### 3.2 输出

根据使用方式不同，`ptoas` 常见输出包括：

- 便于检查或排查的中间表示
- 最终输出代码

## 5. 使用方式

最直接的用法是把 `.pto` 送进 `ptoas`, 生成代码输出的典型形式：

```bash
ptoas input.pto -o output.cpp
```

常见参数包括：

- `--pto-arch=a3|a5`：指定目标架构
- `--pto-level=level3`：控制编译层级
- 与目标、层级、布局和同步相关的开关参数

## 6. 用户最关心的几个问题

### 6.1 `ptoas` 和 `PTO ISA` 的关系是什么？

- `PTO ISA` 是对象模型和 ISA 语义
- `ptoas` 是围绕这套对象模型运行的工具链

没有 `PTO ISA`，`ptoas` 就缺少统一编译对象；没有 `ptoas`，`PTO ISA` 就只是静态定义，无法形成完整使用流程。

### 6.2 `ptoas` 会帮我做什么？

在常见使用路径下，`ptoas` 会帮助用户完成：

- 输入检查
- 目标相关约束检查
- 按选项处理布局、地址和同步问题
- 生成输出代码

## 7. 最小用户路径

对新用户而言，最小使用路径通常是：

1. 准备一个 `.pto` 文件或用 Python 生成 `.pto`
2. 用 `ptoas` 跑通解析和验证
3. 加上目标参数与输出参数，生成 `.cpp`
4. 结合 `test/samples` 或验证脚本检查生成结果

## 8. 设计目标

PTOAS 的设计目标，是把 PTO 的抽象语义稳定地落到可检查、可使用、可生成代码的结构化表示中。

当前这套工具链重点追求：

- 在不同目标路径上维持稳定的 PTO 语义边界，而不是把实现细节暴露给前端
- 以 tile、有效区域、位置、布局和同步为一等概念
- 同时服务 Auto 与 Manual 两类职责模型
- 在 PTO 输入与输出代码之间建立稳定桥接
- 让编译器能显式理解 PTO 对象，而不是依赖后期恢复语义

## 9. 目标用户

PTOAS 面向的不是单一用户群，而是围绕 PTO 程序编写、生成、验证和集成链路上的多类开发者。

主要用户包括：

- 内核与算子开发者：编写或检查 PTO 程序，验证 tile、同步、pipe 和代码生成行为
- 工具链集成者：把 `ptoas` 或生成路径接入更上层构建和运行系统

# 2.7 目标架构与使用差异

## 1. 概述

PTO 的编程模型强调“语义统一、目标有差异”。这意味着文档和 IR 对外提供的是一套稳定的对象模型，但不同目标架构在支持的类型、布局组合、搬运约束和同步要求上可能存在差异。

## 2. 用户如何选择目标架构

当前用户可通过以下方式指定目标：

- `--pto-arch=a3|a5`

建议在编译命令中显式给出目标架构，这样更容易获得稳定且可重复的结果。

## 3. 哪些部分应保持统一

对用户可见的 PTO 编程模型中，下列部分应尽量保持统一：

- 类型系统
- view / tile 对象模型
- 主要操作名与基本语义
- 同步对象与 CV Pipe 语义
- 语法与结构化 IR 组织方式

这保证了：

- 相同 PTO 程序可以在多个目标上共享大部分表达形式
- 相同概念可以在不同目标上保持一致理解

## 4. 哪些部分允许分化

真正可能分化的通常是：

- 某些 op 的支持元素类型集合
- 某些布局 / 位置 / fractal 组合是否合法
- 某些本地数据搬运路径是否可用
- 某些同步或 barrier 的使用要求
- pipe / reserved buffer / workspace 的可用范围

因此，架构差异更多是“同一语义在不同目标上的支持边界不同”，而不是“每个目标都有一套不同语言”。

## 5. 编程模型上的理解方式

写 PTO 程序时，可以把架构说明理解为以下原则：

- 先按统一 PTO 语义表达程序
- 再让编译器告诉你某个实例在目标上是否可接受
- 如果目标需要特殊调整，优先按目标报错或约束调整程序写法，而不是在高层 IR 中提前写入过多目标特化细节

# 5.6 A3 与 A5 的内存差异

## 1. 概述

PTO 语义在不同目标上保持统一，但内存路径、可接受的数据类型、局部数据通路和某些操作的安全实现方式并不完全相同。`ptoas` 会把这类差异收敛到目标相关检查、必要转换和输出生成阶段，而不是让前端文档把它们全部暴露成不同语言。

## 2. 差异的主要体现位置

### 2.1 目标支持边界

不同目标会对实例合法性施加不同约束。例如：

- 某些逐元素操作在 A5 上允许更宽的元素类型集合
- 某些低精度转换只在 A5 上被接受
- 某些操作对 valid row / valid col 的要求会随目标变化

因此，“同一个 PTO op”在不同目标上的语义名字一致，但合法实例集合可能不同。

### 2.2 本地数据通路与搬运约束

本地地址空间的连接关系并不总是完全对称。某些 `tmov` 或同步路径在一个目标上是直接合法的，在另一个目标上则需要额外规避或改写。

### 2.3 pipe / reserved buffer 

CV pipe 和保留 buffer 的某些路径，在不同目标上的本地地址使用方式和工作区依赖也可能不同。因此编译器需要按目标做不同处理。

## 3. 一个典型例子：A5 上的 `tmov` 调整

在 A5 上，某些 `vec -> vec col_major` 的 `tmov` 路径风险更高，编译器会主动把它改写到更安全的形式。

其核心思路是：

- 将相关 tile 先用 `treshape` 重解释为更安全的 `row_major` 形式
- 再执行 `row_major -> row_major` 的 `tmov`
- 保留 alias 语义而不引入真实数据搬运

这说明目标差异不一定表现为“某个 op 完全不可用”，也可能表现为“需要通过目标相关调整，把它改写成另一条安全路径”。

## 4. 地址与同步分析中的目标差异

目标差异不仅影响合法性检查，也会影响同步与内存相关分析，例如：

- 某些 pipeline barrier 的生成策略会因目标不同而变化
- 某些 gather / scatter / pipe 相关组合在特定目标上需要额外规避
- 某些本地地址空间的数据依赖在不同目标上的低层实现路径不同

因此，地址空间相同不等于目标实现路径完全一致。

## 5. 文档层面的理解方式

阅读 PTO 文档时，可以把 A3 / A5 差异理解为两层：

### 5.1 共享层

- 相同的类型系统
- 相同的基本 op 名称
- 相同的 view / tile / sync 对象模型

### 5.2 目标特化层

- 不同的目标支持集合
- 不同的本地搬运或同步规避策略
- 不同的调整与转换细节

第五章关注的不是逐条列举全部差异，而是说明：内存模型本身必须允许这种目标相关分化存在。

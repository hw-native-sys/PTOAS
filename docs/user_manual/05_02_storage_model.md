# 5.2 PTO 存储模型

## 1. 概述

PTO 的存储模型不是“所有对象都看成一块普通内存”，而是明确区分全局对象、本地 tile 对象和宿主辅助对象。这种区分直接体现在类型和操作约束中。

## 2. 三类主要存储对象

### 2.1 全局存储对象

全局存储对象通常位于 `GM`，主要通过以下类型表达：

- `!pto.ptr<T>`
- `!pto.tensor_view<...>`
- `!pto.partition_tensor_view<...>`

它们的角色分别是：

- `ptr`：原始地址入口
- `tensor_view`：全局张量描述符
- `partition_tensor_view`：全局张量的逻辑子区域

这类对象承载的是“如何访问全局数据”，而不是本地计算缓冲本身。

### 2.2 本地 tile 存储对象

本地 tile 对象主要由 `!pto.tile_buf<...>` 表达，并带有显式的：

- 地址空间
- 元素类型
- 物理尺寸
- 有效尺寸
- 布局与 padding

这类对象是矩阵计算、逐元素计算、规约、重排和同步分析的核心对象。

### 2.3 辅助对象

除了 GM 与本地 tile 外，PTO 还显式建模了一些辅助对象，例如：

- `!pto.local_array<...>`
- `!pto.eventid_array<N>`
- `!pto.pipe`

这类对象更多承担运行时辅助、句柄传递或宿主侧局部状态功能。

## 3. 典型数据流

一个典型的 PTO 数据路径通常是：

1. 从 `!pto.ptr<T>` 进入
2. 构造 `!pto.tensor_view<...>`
3. 切分为 `!pto.partition_tensor_view<...>`
4. `tload` 到 `!pto.tile_buf<...>`
5. 在本地 tile 上完成计算
6. `tstore` 回写到分区视图

这条链路说明：

- 全局对象负责描述“从哪里来、写到哪里去”
- 本地 tile 对象负责描述“如何在片上存储与计算”

## 4. 为什么要区分这些对象

区分这些对象的直接作用是：

- 避免把全局视图、本地 tile 和辅助对象混为一谈
- 让每类操作只接受符合语义边界的对象
- 让本地 tile 的位置、布局和有效区域约束更清晰

从用户角度看，可以把它理解为：

- 全局对象主要负责描述输入输出数据
- 本地 tile 对象主要负责片上存储与计算
- 辅助对象主要负责事件、句柄或局部辅助状态

## 5. 重要区别

### 5.1 视图不是存储

`tensor_view` 和 `partition_tensor_view` 不拥有数据，只描述一段全局存储的逻辑解释方式。

### 5.2 tile_buf 是本地存储对象

`tile_buf` 是带地址空间和布局的本地缓冲对象，不是简单的“张量值”。

### 5.3 宿主对象不等于片上对象

`local_array`、事件数组和部分句柄类型虽然也是“可用对象”，但它们不承担片上 tile 存储语义。

# 1.1 什么是 PTO

## 1. 范围

本文档说明 `ptoas` 语境下 PTO 的定位、抽象层次、核心对象以及 `ptoas` 围绕 PTO 提供的主要能力。

本文档只讨论 PTO 作为 `ptoas` 中抽象指令集和 `PTO ISA` 对象模型的部分，不展开具体前端库、样例工程或后端实现细节。

---

## 2. PTO 的定义

PTO 是一套面向 tile 编程的抽象指令集。

它不是某一条具体指令，也不是某一种单独的后端实现，而是一组稳定的抽象语义，用来统一表达：

- tile 级计算
- 全局内存与片上对象之间的数据搬运
- 有效区域、位置和布局约束
- 事件、同步与顺序关系
- 运行时辅助与调试行为

在 `ptoas` 中，PTO 的这些抽象语义被实现为 `PTO ISA` 及其相关编译流程。两者的关系可以概括为：

- PTO 定义“表达什么”
- `ptoas` 定义“如何表示、检查、变换并生成它”

PTO 给出抽象语义边界，`ptoas` 给出工程化实现。

---

## 3. PTO 的定位

PTO 位于前端编程模型与目标后端实现之间。它的定位可以概括为：向上，为前端和编译器提供统一的 tile 语义接口向下，为合法化、优化和代码生成提供稳定的中间抽象。这层抽象既不能过高，也不能过低。如果过高，只保留普通张量计算语义，那么很多关键语义会丢失，例如：tile 的物理 shape，valid shape，数据所在位置，布局与分形信息，显式同步关系，片上资源复用意图，如果过低，直接暴露全部实现细节，那么程序与工具链就会快速与某一类具体实现耦合，难以复用、验证和演进。

因此，PTO 的作用是在“过于抽象”和“过于具体”之间建立稳定边界。

---

## 4. PTO 解决的问题

### 4.1 统一 tile 级对象模型

PTO 不是围绕任意 tensor 运算设计的，而是围绕 tile 对象组织语义。这样可以直接表达：

- 片上缓冲区
- 局部计算粒度
- 数据搬运边界
- 显式的消费/生产关系

### 4.2 为结构化编译流程提供稳定表示

PTO 不只是概念上的指令集，还需要落成一套结构化对象模型，供工具链处理。

在 `ptoas` 中，这体现为：

- PTO 文本表示
- 类型、属性和操作定义
- 编译检查
- Pass 流水线
- 代码生成与字节码路径

---

## 5. PTO 的核心抽象对象

### 5.1 Tile

Tile 是 PTO 最重要的基本对象。大多数计算和搬运操作都围绕 tile 展开。

一个 tile 通常不只包含元素类型和 shape，还显式携带：

- 所在位置
- 有效区域
- 布局信息
- padding 或其他附加配置

### 5.2 全局视图与分区视图

PTO 并不把全局内存简单建模为“裸指针 + 任意地址偏移”，而是通过视图对象表达全局张量及其逻辑切片。

在 `PTO ISA` 中，这通常表现为：

- `!pto.ptr<T>`
- `!pto.tensor_view<...>`
- `!pto.partition_tensor_view<...>`

### 5.3 位置与布局

PTO 把位置和布局提升为一等语义，而不是仅在后端隐式处理。

常见位置包括：

- `vec`
- `mat`
- `left`
- `right`
- `acc`
- `bias`

常见布局信息包括：

- `row_major`
- `col_major`
- `none_box`
- 分形大小

### 5.4 有效区域

PTO 明确区分对象的物理容量和当前有效区域。

这意味着很多操作的语义并不是对整个物理 tile 生效，而只对有效区域生效。尾块、不满块、padding 和部分结果写回都依赖这套语义。

### 5.5 同步与顺序

PTO 不是默认串行执行模型。它允许不同阶段和不同资源在依赖允许时并行推进，因此同步关系必须显式表达。

在 `ptoas` 中，这通常表现为：

- 高层事件语义
- 低层 flag / barrier / pipe 同步
- 自动同步插入

---

## 6. PTO 在 `ptoas` 中的表示

在 `ptoas` 中，PTO 被实现为一套完整的 `PTO ISA`。

其对象模型主要包括：

### 6.1 类型系统

PTO 的核心对象不是靠零散 attribute 拼装出来的，而是通过显式类型表示，例如：

- `!pto.ptr<T>`
- `!pto.tensor_view<...>`
- `!pto.partition_tensor_view<...>`
- `!pto.tile_buf<...>`
- `!pto.pipe`

### 6.2 操作系统

PTO 的抽象指令在 `ptoas` 中被实现为一组 PTO ISA 操作，主要类别包括：

- 指针与 view 操作
- tile 生命周期与数据搬运操作
- 向量算术和矩阵计算操作
- 归约、广播、重排与转换操作
- 同步操作
- pipe、运行时和调试辅助操作

### 6.3 验证与约束系统

PTO 的很多约束不能只靠文本格式保证，而需要通过编译检查显式判断，例如：

- 类型是否匹配
- 位置是否兼容
- valid shape 是否合理
- 属性组合是否合法
- 某些操作是否满足目标相关限制

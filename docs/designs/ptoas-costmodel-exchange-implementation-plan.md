# PTOAS × Cost Model 实施与验收计划

状态：实施中；2026-09-18 已完成固定 stress micro 的预冻结四组消融验收。
TileSim 推荐 P=1、P Buffer 双槽；A5 配对实测 B/A 收益 14.64%、B/P0 收益 15.39%，
仅加槽的 M/P0 为 -0.72%，通过 `MECHANISM_BENEFIT_PASS`。TileSim 绝对预测误差 24.02%，
因此不签发 G4，自动优化仍关闭。

设计依据：[交换协议 ADR](ptoas-costmodel-exchange-v2.md)、[v1 契约](ptoas-cv-costmodel-exchange-v1.md)
及 [CV 流水设计 #1292](https://github.com/hw-native-sys/PTOAS/pull/1292)。
本计划区分已落地的受限实现与后续通用能力，不修改已经保存的历史测试证据。

## 目标与范围

在保留模型无关协议、独立 adapter、稳定 Buffer ID、ownership 和默认 annotation-only 的基础上，
明确模型使用的内存假设，并验证最终编译是否兑现这些假设。继续采用 `Pe=min(P,N)` 的候选调度语义。
当前不增加用户可见 annotation；优先完善编译器内部来源追踪、外部报告与协商能力。

首个范围仍为 A5、静态 shape、单轴静态循环、tile entry、固定四阶段图、核内调度关闭。
未支持的别名、递推、多轴和动态输入明确拒绝。未知耗时、资源或安全条件不能按零处理。

## 近期阶段：来源、内存契约与 G2 门槛

| 工作项 | PTOAS 交付 | Cost Model / TileSim 配合 | 通过条件 |
|---|---|---|---|
| A1 契约冻结 | ADR、扩展 schema、必需能力、版本兼容规则 | 审核可消费的字段和覆盖声明 | 固定 golden 包；旧 v1/2.0 行为保留；未知必需能力被拒绝 |
| A2 来源追踪 | Buffer→版本→槽→物理分配关系；消除/拆分/临时对象状态 | 消费显式来源，不从 SSA/地址推断 | 多槽降低后每个存储对象有来源或明确生成原因；地址复用不合并逻辑身份 |
| A3 内存估算契约 | 分离依据、覆盖、可行性；分核/存储域核算 | 声明复用假设和未知存储 | 保守求和超预算标为待规划；不误判为物理不可行 |
| A4 有界规划试跑 | 独立尝试次数/时间预算、实际布局检查、分类诊断 | 接受待定/超时/不支持状态 | 能处理求和超预算但复用可放的候选；失败不缩槽，不污染下一候选 |
| A5 完成事件与 G2 | 访问完成/释放条件、同步证据、加入复用边后的依赖及 FIFO 检查 | 估计时间但不提供唯一安全依据 | 所有必要条件通过才标 G2；unknown 保持未通过 |
| A6 双方重放签收 | 固定 micro、输入/候选/产物指纹与逐项报告 | 在团队环境独立运行真实 adapter | 同一输入和候选的 G1 联合记录；G2 按实际证据单独签收 |

A2 需覆盖 materialization、多槽 lowering、PlanMemory 和同步/后续变换的来源维护。
不能只保留原始 allocation 上的一个字符串，再假定后续天然继承。最终映射应由编译器对象直接导出。
A3 的估算值只有在列明覆盖范围后才可解释；未知临时存储不能被称为最终程序保守上界。
A4 的规划失败仅代表本次编译器策略未实现候选，超时也不等于容量不足。

A5 若暂时缺乏异步安全证明，允许交付来源/布局报告和候选编译结果，但不允许提前签收完整 G2。
保守等待只有实际插入、校验并纳入后续成本反馈后才能作为支持路径。

| B2 假设核对 | 比较逻辑候选与实际执行/资源变化；报告预测有效性 | 声明布局、等待和地址相关成本能力 | 只有经核对等价才能保留预测；其余重新评估或明确 unsupported |
| B3 模型重新评估 | 可重放调用、反馈版本和缓存失效 | 补齐 A5 L2L/释放计时、profile 对齐、成本校准和计时生命周期分析 | 同一实际候选返回绑定的新预测；不支持项不按零成本处理 |
| B4 正确性与性能 | 独立 golden、设备执行、超时/死锁/越界检查、测量与回退 | 对照预测误差及候选排序 | 分别取得 G3、G4；按明确认证范围决定自动启用 |

模型侧扩展字段与 feature 名称在 A1 冻结前均为提议。本轮编译器反馈已采用独立版本的
`pto.compiler_memory.v1` 和 `pto.compiler_validation.v1`，不让旧 adapter 静默接收新语义。
G2 与预测有效性是不同状态：合法编译可以没有有效耗时预测，但不能以旧预测进入收益认证。
反馈后的预测缓存额外绑定最终布局、执行约束、编译器流水配置与模型配置；测量缓存还绑定设备环境。
降低流程继续改变成本时产生新反馈版本，旧认证和旧预测不能直接沿用。

现有固定静态候选的 G3 工具准备可以与 B3 并行，性能签收必须等待有效的实际候选评估。
此前配置的 A5 主机连接失败是历史环境状态；启动设备验证前需重新检查连接与工具链。

## 新增验收矩阵

以下 M01–M12 是待实现测试要求，不包含在已有 31 项 v2 测试通过数中。

| ID | 场景 | 必须得到的结果 |
|---|---|---|
| M01 | 不同 Buffer 合法复用同一地址 | 保留不同来源；同一物理存储域按实际布局核算，完成条件有证据 |
| M02 | preload 使生命周期重叠 | 重新分配或插入合法等待；新增资源/等待进入反馈，旧预测重新核对 |
| M03 | 异步消费者已发射但未完成 | 禁止覆盖；有正确完成依赖时才允许复用 |
| M04 | 1/2/3 槽降低为物理分配 | 各槽和版本可追溯；被消除对象显式记录，不伪造分配 |
| M05 | 两个 AIV 地址数值相同 | 按独立物理域核算；不能错误去重或合并身份 |
| M06 | 修改候选/target/编译器配置后重编译 | 旧布局映射、反馈预测和测量证据不能误命中 |
| M07 | 求和超预算但复用后可放 | 进入受预算控制的规划试跑；合法布局成功后才确认可行 |
| M08 | 复用新增等待导致依赖/FIFO 环 | 拒绝该候选；不能因原调度检查通过而跳过最终检查 |
| M09 | adapter 不支持新增等待成本 | 旧完整预测失效；保留覆盖限制，不得宣称零成本或已认证 |
| M10 | 后续产生临时存储、对齐空洞或拆分 allocation | 来源完整；实际预留空间和容量检查反映这些变化 |
| M11 | 规划失败、超时、不支持、协议损坏 | 分类报告；前三者不混成普遍不可行，协议损坏终止请求；失败不发布部分产物 |
| M12 | 布局/执行报告与候选产物不匹配 | 拒绝反馈；即使输入配置相同也不得复用旧预测 |

测试同时覆盖成功与失败路径。G2 每项检查都要输出 pass/fail/unknown 及证据引用，不能只统计同步指令数量。
延迟预测、资源估计和正式认证各自声明覆盖范围，不能用模型预测的完成时间代替编译器安全证明。

## 2026-09-16 固定推荐 A/B 增量

- TileSim 将显式 stage schedule 降成 MIR，使用 channel 表达核间依赖和每核 stage 顺序，
  由现有 planner/EventEvaluator 计算候选端到端时延；vector stage 同时展开 AIV0/AIV1。
- `tilesim.selection.v1` 固定 0.5% tie、2% 推荐门槛和 memory/Pe/ID 顺序。PTOAS 对 ranking、
  candidate、latency、configuration 和 baseline 做严格绑定，并保存 `selected-plan.json`。
- `prepare_ab.py` 在测量前冻结模型结果并生成 A/P0/B；`run_ab.py` 实施三种子 G3、20 个
  AB/BA block 和 P0 诊断；`summarize_ab.py` 实施固定种子 bootstrap 与 10% 预测误差门槛。
- 旧 adapter 无该扩展时保持原行为；旧 certification policy 不带 paired 字段时保持原算法。
  新工具已在干净冻结提交和全新私有实验中完成本轮 baseline-retained 验收；结果见
  [固定推荐 A/B 验收记录](ptoas-costmodel-ab-acceptance-20260916.md)。只有未来冻结选择返回
  optimize 时，才进入 20 个 AB/BA block 和预测误差认证。
